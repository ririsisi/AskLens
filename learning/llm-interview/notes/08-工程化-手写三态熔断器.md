## 一、三个状态与转换（面试必背）

```
CLOSED（关闭/正常）  正常放行；连续失败达阈值 → OPEN
OPEN（打开/熔断）    拒绝所有请求；超时窗口到期 → HALF_OPEN
HALF_OPEN（半开/探测） 放行探测请求；连续成功达阈值 → CLOSED；任一失败 → OPEN
```

- 三个可调参数：`failure-threshold`（默认 5）、`success-threshold`（默认 3）、`timeout-seconds`（默认 30）。
- 关键点：**OPEN 不是永久的**，靠"超时后转 HALF_OPEN 探测"自动恢复；HALF_OPEN 是"半信半疑"的试探期，一次失败立刻退回 OPEN。

## 二、线程安全实现要点（容易被追问）

- 状态用 `AtomicReference<State>`，计数用 `AtomicInteger`，转换用 **CAS（compareAndSet）** 而不是普通赋值——保证高并发下多个请求不会把状态改乱（如两个线程同时把 OPEN 改成 HALF_OPEN，只有一个成功）。
- `openedAt` 用 `volatile Instant` 记录熔断起点，判断超时窗口。

核心骨架（记结构即可，别背全文）：

```java
private final AtomicReference<State> state = new AtomicReference<>(State.CLOSED);
private final AtomicInteger failureCount = new AtomicInteger(0);
private final AtomicInteger successCount = new AtomicInteger(0);
private volatile Instant openedAt;

boolean allowRequest() {
    switch (state.get()) {
        case CLOSED:    return true;
        case OPEN:      // 超时则 CAS 转 HALF_OPEN 放行探测
            if (timeoutExpired() && state.compareAndSet(OPEN, HALF_OPEN)) successCount.set(0);
            return state.get() == HALF_OPEN;
        case HALF_OPEN: return true;
    }
}
// recordSuccess: HALF_OPEN 下成功累加，达 successThreshold → CAS 转 CLOSED
// recordFailure: CLOSED 下失败累加，达 failureThreshold → CAS 转 OPEN；HALF_OPEN 下任一失败 → CAS 转 OPEN
```

## 三、和模型路由配合（降级模式）

`ModelRouter` 把熔断器套在 LLM 调用外层，实现自动降级：

1. `selectModel()`：熔断器 `allowRequest()` 为 false 时，直接选**备用小模型**（gpt-4o-mini）而非主模型；
2. `call()`：主模型抛异常 → `recordFailure()` + 降级到备用模型重试；成功 → `recordSuccess()`；
3. 备用模型也挂 → 抛"所有模型不可用"。
4. 流式 `stream()` 用 `onErrorResume` 在主模型出错时切到备用模型流。

**降级层次**（面试可讲）：主模型 → 备用小模型 → 兜底话术/缓存。

## 四、30 秒面试话术（待你改写）

> 熔断器是三态状态机：正常 CLOSED 放行并统计失败率，连续失败超阈值跳到 OPEN 直接快速失败、避免拖垮上游；OPEN 等一个超时窗口后进 HALF_OPEN 放少量探测请求，连续成功才回 CLOSED，探测失败立刻退回 OPEN。我用 AtomicReference + CAS 保证状态切换的并发安全。它常和模型路由配合做降级：熔断打开时自动切到备用小模型，再不行就走缓存或兜底话术。
